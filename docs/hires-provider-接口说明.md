# 高分辨率图片提供者（hires provider）接入说明

> 本文件只描述**接口契约**，不含任何实现。
> 本项目自带的图片链路（本地 `.dat` 解密）在没有 provider 时也能工作，
> 只是分辨率较低（缩略图级）。装上 provider 后自动升级到全分辨率原图。

---

## 一、它解决什么问题

微信收到图片时，客户端本地缓存可能只有缩略图（几十 KB，200~500px），
文字类截图在缩略图里读不出来。

**provider 的作用**：在本机把「同一张图的全分辨率版本」写到约定目录，
机器人识别时会优先用那份，于是能读出图里的文字。

---

## 二、契约（就这一条）

### 2.1 目录

```
默认：D:\cdndl-replay
可用环境变量覆盖：WECHAT_HIRES_DIR=<目录>
```

目录必须存在且可写。**建议用纯 ASCII 路径**（含中文的路径在部分组件里会失效）。

### 2.2 文件名

```
<roomId>_<unix秒>_<localId>_<任意序号>_<任意标记>.dat
```

| 字段 | 含义 | 必需 |
|---|---|---|
| `roomId` | 会话 ID，如 `12345678@chatroom` 或对方 `wxid_xxx` | ✓ |
| `unix秒` | 该消息的服务端时间（**秒**，10 位数字） | ✓ |
| `localId` | 该消息在本地库的 `local_id`（纯数字） | ✓ |
| 其余 | 序号 / 标记，随便填，桥不解析 | — |

例：

```
12345678@chatroom_1792572971_400_1_t2_s5.dat
12345678@chatroom_1792572971_400_big.dat
```

### 2.3 内容

**必须是未加密的图片字节**（JPEG / PNG / WebP / GIF）。
桥会直接把它当图片读，**不做任何解密**。

> ⚠️ 常见的错误做法是把微信的 `.dat`（V2 AES+XOR 加密）原样拷过来 —— 那样桥读不了，
> 会退回自己的解密链路（等价于没装 provider）。

### 2.4 时序

```
消息到达 → 桥等最多 8 秒（每 250ms 查一次）→ 找到就用 → 找不到走本地解密
```

所以 provider 只要在**消息到达后 8 秒内**写好文件即可。

---

## 三、桥怎么选文件

同一时刻目录里可能有多张图，桥的规则：

```
1. 文件名第一段 == 当前会话 ID
2. 文件名第二段（unix秒）与当前消息时间相差 ≤ 5 秒
3. 文件大小 > 3KB（避免读到写了一半的）
4. 满足条件的里面取【最大】的那张   ← 缩略图小，原图大，自然选对
5. 复制成 .jpg 交给识图（原 .dat 不动）
```

**这意味着**：provider 一次写多份（小图+大图）也没关系，桥会挑最大的。

---

## 四、没有 provider 会怎样

```
桥：高分辨率缓存未命中（ts=...），改走本地 .dat
→ 按 _h 高清预览 → 中图 → 缩略图 的顺序解密
→ 能看懂「是什么图、什么人、在干嘛」，但图里的字多半读不出
```

**功能不缺，只是画质降级。**

---

## 五、磁盘与清理

```
· 每张图 0.1 ~ 1.5MB
· 桥会自动清理：保留最新 60 个 + 2 小时内的，其余删掉
· 目录里都是聊天图片，属于隐私数据，不要上传、不要共享
```

## 六、获取 provider

实现方式不随本项目分发（涉及对客户端内部接口的分析，不在开源范围）。

如果你确实需要，请联系项目作者获取**预编译组件**，
并自行确认：它需要与你当前微信客户端的具体版本严格匹配，
版本不对会失效甚至引发客户端异常。风险与合规责任由使用者自行承担。

---

## 七、自测方法

把任意一张 JPEG 按契约命名丢进目录，然后让群里发一张图，看桥日志：

```
桥：高分辨率缓存命中：<你的文件名>（xxxKB）
插件：识图成功：……
```

如果看到「高分辨率缓存未命中」，逐条对照：

```
□ 目录存在且是 ASCII 路径
□ 文件名第一段与会话 ID 完全一致（含 @chatroom）
□ 第二段是 10 位 unix 秒（不是毫秒）
□ 内容是真的 JPEG（file 头 ff d8 ff），不是加密 .dat
□ 文件大小 > 3KB
```

## 十、视频（可选）

provider 除了图片，也可以提供**视频的完整内容**（mp4），契约同样简单：

### 文件名

```
<roomId>_<unix秒>_<localId>_<任意序号>_<含 video 的标记>.dat
```

**唯一额外要求**：文件名里要出现 `video` 字样（桥靠它区分「这是视频」），
例如 `..._hdvideo_s0.dat`。

### 内容

**未加密的 MP4**（H.264/AAC 等常见编码即可，ffmpeg 能解就行）。

### 大小与完成判定（重要）

桥会**等文件写完**才使用，判定标准：
1. 连续两次采样（间隔 300ms）大小一致
2. 文件大小 ≥ 消息声明大小的 55%（若知道声明大小）

> ⚠️ 曾经的坑：文件还在写就复制 → 拿到半截视频 → 抽帧/时长/音轨全对不上，
> 机器人就会描述错误的视频。**provider 侧也请"写完再落盘"**（先写临时名，写完再改名）。

### 桥拿到视频后做什么

```
每秒 1 帧抽帧（上限 60 帧）→ 每 20 帧一张联系表 → 逐张识别
全程音轨转 16k WAV → 语音模型转写台词
识别完删除临时文件（含视频副本），不占磁盘
```

### 没有视频 provider 时

退回「微信本地已落盘的视频」；再没有就只用封面（静态一帧）——
**功能不缺，只是看不到过程**
