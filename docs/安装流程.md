# 完整安装流程（正确顺序）

> 本文只讲**怎么装**。装之前请确认：Windows 10/11 x64、微信 **4.1.10.27**（目录名必须是 `4.1.10.27`）、Node.js ≥ 20、Python 3.11（语音合成/识图用）。
>
> 两条路线二选一：
> - **A. 用成品**（不会编译也能装）：克隆仓库后直接用 `release/` 目录里的 `version.dll` + `install.ps1`（或从 GitHub Releases 下载同样文件）
> - **B. 自己编译 hook**：有源码 + 补丁，用 VS2022 Build Tools 编出 `version.dll`

---

## 一、先理解整体结构

```
微信客户端 (Weixin.exe)
   └─ 同目录 version.dll  ← hook 代理：消息/数据库/发送/眼睛
        ├─ HTTP 接口 127.0.0.1:30001   （读库 / 发消息 / 诊断）
        └─ 消息回调 127.0.0.1:18998    （新消息推给桥）

wx-bridge（Node.js）ws://127.0.0.1:17300
   ├─ 连 30001 读写微信
   └─ 连 DSH 插件（WebSocket 17300）

DSH + wechat-group-agent 插件
   └─ 控制面板 /wechat-bot
```

**没有 `version.dll` 就什么都做不了**（读不到消息、发不出消息）。

---

## 二、安装 hook（version.dll）

### 2.1 路线 A：用成品包

1. 解压 `大肥鱼的眼睛.zip` 到任意目录（**不要解压到 `%TEMP%`**，Defender 可能把里面的 dll 当可疑文件删掉）
2. 完全退出微信（托盘右键 → 退出微信），确认任务管理器里 `Weixin.exe` 进程数为 0
3. 运行 `install.ps1`（一键安装）（会自动备份旧 dll 再覆盖）；或手动把 `version.dll` 复制到微信目录
4. 安装完成后，确认微信目录里有：
   ```
   version.dll
   hook-cdn-replay.on      ← 眼睛重放开关
   hook-cdn-replay.dir     ← 重放缓存目录（内容 D:\cdndl-replay）
   ```

### 2.2 只有原版 hook：怎么编译、以及为什么不能直接用

**先说结论**：原版 `aixed/WeChat-Hook` 是给微信 **3.9.x** 的，按本文档的微信 4.1.10.27，**编出来也接不上**。原因不是编译失败，而是：

1. **偏移不对**：原版把 sqlite API 表、发送函数、图片密钥等偏移写死成 3.9.x 的值。4.1.10.27 的函数位置全变了 → 钩子装上也是空的，`/QueryDB/execute` 恒报 `get database handle which named contact.db failed`。
2. **端点不全**：本桥依赖的 `/SendVoiceMsg`、`/Decode_Pic`（4.x 图片解密）、`/Debug/DBRescan`、`/Debug/VuProbe`、`/Debug/VoiceSend`、`/GetSelfProfile`，原版都没有。
3. **缺 4.x 开库入口**：微信 4.x 主要走 `open16`（宽字符文件名），原版只挂了 `open`/`open_v2`，而且构造时 API 表还没填好（需要 **late-arm** 补装）。

所以"只有原版源码"的用户只有两条路：

- **路 1（推荐）**：从 **GitHub Releases** 页直接下载 `version.dll` + `install.ps1`（一键安装）（散文件，无需解压）；
- **路 2**：按下面的步骤 ① 编出原版，再按步骤 ③ 自己补齐 4.1.10.27 的偏移与接口（需要逆向能力）。

---

#### ① 编译原版（照做即可）

**前置**

- Windows 10 / 11 x64
- Visual Studio 2022 **Build Tools**，安装时勾选：
  - 「使用 C++ 的桌面开发」（MSVC v143）
  - Windows 10 / 11 SDK
- Git for Windows

**命令**

```powershell
# 1) 拉源码
git clone https://github.com/aixed/WeChat-Hook.git wxhook-src
cd wxhook-src

# 2) 拉子模块（MinHook 等，不拉会编译报错）
git submodule update --init --recursive

# 3) 找 MSBuild
$vswhere = "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe"
$msbuild = & $vswhere -latest -requires Microsoft.Component.MSBuild `
            -find "MSBuild\**\Bin\MSBuild.exe" | Select-Object -First 1

# 4) 编译
& $msbuild x64_Version_dll.sln /p:Configuration=Release /p:Platform=x64 /m

# 5) 产物
Get-Item .\x64\Release\version.dll
```

**部署**

1. 完全退出微信（任务管理器里 `Weixin.exe` 进程数为 0）
2. 把 `version.dll` 放进 `Weixin.exe` 同目录（如 `D:\wxhook\wx4110\`）
3. 启动微信（带 hook 参数）：
   ```powershell
   Start-Process 'D:\wxhook\wx4110\Weixin.exe' `
     -ArgumentList 'StartPort=30001','RecvType=1','CallBackURL=http://127.0.0.1:18998/recv' `
     -WorkingDirectory 'D:\wxhook\wx4110'
   ```
4. 验证：
   ```powershell
   Invoke-RestMethod http://127.0.0.1:30001/QueryDB/status
   ```

**预期结果**：返回 404、连接被拒绝，或 `IsLogin:0` —— 这就是上面 3 条原因造成的，说明**原版不能直接接入**。

#### ② 桥依赖的接口契约（补齐目标）

补齐这些端点后，本机器人才能工作。表格里的字段与 `wx-bridge` 的实际调用一致：

| 方法 | 路径 | 请求体 / 参数 | 响应 |
|---|---|---|---|
| GET | `/QueryDB/status` | — | `{"IsLogin":1,"hWeixin":123456}` |
| POST | `/QueryDB/execute` | `{"optDbName":"message_1.db","SQL":"SELECT ..."}` | `{"status":0,"data":[...]}` |
| POST | `/QueryDB/GetAllDBName` | `{}` | 库名列表（可为空实现） |
| POST | `/GetSelfProfile` | `{}` | `{"wxid":"wxid_xxx","nickname":"..."}` |
| POST | `/SendTextMsg` | `{"wxidorgid":"123@chatroom","msg":"你好","atlist":"wxid_a,wxid_b"}` | `{"ret":0}` |
| POST | `/SendImgMsg` | `{"wxidorgid":"123@chatroom","path":"C:\\a.jpg"}` | `{"ret":0}` |
| POST | `/SendVoiceMsg` | `{"wxidorgid":"...","path":"C:\\a.silk","durationMs":2000}` | `{"ret":0}` |
| POST | `/Decode_Pic` | `{"src_path":"C:\\in.dat","dst_path":"C:\\out.jpg"}` | `{"ret":0}` |
| POST | `/Debug/VoiceSend` | `{"on":true}` / `{}` | `{"enabled":true}`（语音开关，可选） |
| POST | `/Debug/DBRescan` | `{}` | 句柄注册表快照（诊断，可选） |
| GET | `/Debug/VuProbe` | — | 眼睛 9 钩子状态（可选） |

> 前 8 个是**必需**的；后 3 个只影响控制面板的诊断/语音/眼睛功能。

---

#### ③ 补齐这些要做什么（技术路线，不含具体偏移值）

1. **重新定位偏移**：用 x64dbg / Cheat Engine 配合特征码，找到 4.1.10.27 的：
   - `sqlite3_api_routines` 表地址
   - `open` / `open16` / `prepare` / `step` 真实函数地址
   - 文本/图片/语音发送函数（`SendText`/`SendImage`/语音工厂 + 内层 ctor）
   - 图片解密所需密钥函数
2. **把偏移集中管理**：全部放进一个头文件（如 `include/global.h` 的 `offset::` 命名空间），换微信版本只改这一处。
3. **late-arm**：微信 4.x 的 API 表在 DLL 加载后才填好，构造时 `api->open16` 还是空指针。要在**每次查询前**检查并补装缺失钩子（幂等），否则 `contact.db` 永远登记不上。
4. **按 ② 的契约实现端点**：`/QueryDB/execute` 用客户端自己的 `prepare`/`step` 句柄执行，不要新开连接（库是加密的，密钥在客户端里）。
5. **部署后验证顺序**：
   ```powershell
   Invoke-RestMethod http://127.0.0.1:30001/QueryDB/status            # IsLogin=1
   # 微信里点一次「通讯录」，再查：
   Invoke-RestMethod http://127.0.0.1:30001/QueryDB/execute -Method Post `
     -Body '{"optDbName":"contact.db","SQL":"SELECT count(*) FROM sqlite_master"}' `
     -ContentType 'application/json'                                   # status=0
   ```

#### ④ 编译 / 部署常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `MSB8020：找不到 v143 工具集` | 没装 C++ 工作负载 | VS Installer 勾「使用 C++ 的桌面开发」 |
| `无法打开 include 文件 "httplib.h"` | 子模块没拉 | `git submodule update --init --recursive` |
| `C1083：无法打开 "Windows.h"` | 缺 Windows SDK | 勾选 Windows 10/11 SDK |
| `LNK1104：无法打开 version.lib` | 旧的中间产物冲突 | 删 `x64\` 目录后重编 |
| 编出来微信启动就崩 | 源码与微信版本不匹配 | 必须 4.1.10.27；换对应版本源码 |
| `QueryDB/status` 404 / 拒绝连接 | DLL 没被加载 | 确认放在 `Weixin.exe` 同目录、微信确实重启过 |
| `IsLogin:0` 且库读不到 | 偏移不匹配（原版对 4.x 无效） | 按 ③ 重新定位偏移 |

## 三、启动微信（必须带 hook 参数）

```powershell
Start-Process -FilePath 'D:\wxhook\wx4110\Weixin.exe' -ArgumentList `
    'StartPort=30001','RecvType=1','CallBackURL=http://127.0.0.1:18998/recv' `
    -WorkingDirectory 'D:\wxhook\wx4110'
```

- 登录窗口出现时点 **「进入微信」**
- 验证 hook 已加载：
  ```powershell
  Invoke-RestMethod http://127.0.0.1:30001/QueryDB/status
  # 期望：{"IsLogin":1,...}
  ```

> ⚠️ **登录成功后，务必在微信里点一次左侧「通讯录」图标，停留 3 秒。**
> 微信的 `contact.db` 只在打开通讯录/搜索联系人时才真正打开；
> 不点这一步，桥会报 `get database handle which named contact.db failed`，
> 表现为：群成员为空、名字只显示 wxid、真 @ 退化成纯文本 @。


验证：


首次启动如果提示「数据库轮询硬停」，在微信里点一次通讯录后执行：


## 五、启动 DSH + 插件

1. 启动 DSH web（默认 `http://127.0.0.1:3080`）
2. 确认插件已装配（profile 的 `cordis.patch.yml` 里有 `dsh-wechat-bot` 条目，且 `disabled` 不为 true）
3. 左侧面板列表应出现 **🐋 微信机器人**，点击打开控制面板
4. 面板「总览」点 **立即自检**，应全部 ✅（`filehelper` 那项提示可忽略——它不是群）

---

## 六、语音发送（默认关闭，需要手动开）

1. 面板「语音」页 → 🔌 hook 语音发送开关 → 打开
2. 该开关会同时创建 `hook-voice-send.on` 标记文件（重启微信后仍生效）
3. 语音页把 `voiceSay` 打开、`voiceSayProbability` 调到想要的值（0.2 = 约 5 条里 1 条用语音）
4. 测试：面板「手动操作」→ 操作选「发语音（合成）」→ 选群 → 输入文字 → 发送

> 合成（TTS）需要联网；合成/发送失败会自动降级发文字，不会丢消息。

## 九、常见坑（都是实际踩过的）

| 现象 | 原因 | 处理 |
|---|---|---|
| `get database handle which named contact.db failed` | 微信还没打开 contact.db | 微信里点一次「通讯录」，再 `POST /api/pollResume` |
| 群成员空、名字是 wxid、@ 变纯文本 | 同上 | 同上 |
| 语音发不出去（ret=-1005 / preflight 失败） | DLL 是旧版（preflight 不放行 0xE9） | 换成本仓库配套的新版 `version.dll` |
| 面板语音开关重启后失效 | 旧版 DLL 只改内存 | 新版会在切换时写 `hook-voice-send.on` 标记文件 |
| 换 dll 报「文件被占用」 | 微信还在跑 | 完全退出微信（进程数 0）再换 |
| 解压出来的 dll 找不到了 | Defender 把 `%TEMP%` 里的 dll 删了 | 解压到微信目录或非 Temp 路径 |
| 面板 🐋 消失，但机器人还在回消息 | 插件 entry 被标了 `disabled: true`（热重载副作用） | 重启 `dsh web`，或让 entry 复位后重新启用 |
| 插件热重载后代码不生效 | ESM 模块缓存没清 | 重载前清 `loader.internal.loadCache` 里该包的缓存 |

## 十、回滚

用成品包里的 `rollback.ps1`（一键回滚），或手动：

1. 完全退出微信
2. 把 `version.dll.bak-<时间>` 复制回 `version.dll`
3. 重新启动微信

## 十一、不要上传到 GitHub 的东西

- `version.dll`（hook 二进制）
- `大肥鱼的眼睛*.zip` / 任何 `*.zip`
- `patches/*.patch`（含 Weixin.dll RVA 地址的源码补丁）
- `scripts/gen-offset-patterns.py`（RVA 特征码生成器）
- `docs/*-re.md`（逆向笔记）
- `config.json`（真实 wxid / 密钥 / 本机路径）
