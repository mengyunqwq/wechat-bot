> 这份文档记录本项目**实际踩过的坑**，不是理论清单。
> 每条都写清：**症状 → 根因 → 怎么判断 → 怎么解**。
>
> 遇到问题先看「一、症状速查」，再看对应小节。

## 二、机器人不说话

### 2.1 微信没登录

**症状**：面板顶栏「微信」pipeline 是灰色/未登录；桥日志刷 `检测到客户端已退出`。

**判断**：

```powershell
# 微信进程在不在
(Get-Process -Name Weixin -EA SilentlyContinue).Count
# 应该 >= 1；0 = 微信没起
```

**怎么解**：启动微信并登录。**注意本项目不会自动拉起微信**（设计如此，见 `OPERATIONS-RULES.md` R2）。

---

### 2.2 轮询硬停（最重要的一条）

**症状**：

```
桥上能说话（你手动发消息能发出去），
但群里别人说话它完全收不到 —— 而且日志看起来还挺正常。
```

**桥日志里会出现**：

```
轮询彻底停止（探测连续失败 3 轮）—— 不再自动重试，避免反复探测把微信搞崩。
恢复方式：微信重新登录 / POST /api/pollResume / 重启桥
```

或者：

```
数据库轮询硬停（init 连续失败 6 次）—— 不再自动重试，...
```

**根因**（2026-10-22 实测，两次崩溃都因为这条链）：

```
微信的 message_*.db 是懒加载的，要靠 hook 拦截 sqlite3_prepare 才能拿到句柄。
DLL 里有个 trusted-handle 判断：
    trusted = (fail < 2) && (nowMs() - tick < 300000)
其中 tick 是「微信 open 这个库的时间」，**不是「上次成功读的时间」**。
微信启动后 open 一次，tick 就固定在那儿；超过 5 分钟 → 判不可信 →
retireHandle() 立墓碑 → 重扫又可能拿到不正的句柄 → 反复探测 → 野指针 → 微信崩。
```

**为什么加了硬闸**：以前是 `60s → 120s → 240s → ... → 600s` **无限退避**，每次都戳微信。现在最多试 3 轮（tick 路径）或 6 次（init 路径）就彻底停手。

**怎么解**（三种，按推荐顺序）：

```powershell
# ① 让微信重新打开消息库 —— 在微信里点开任一聊天窗口（最快，几秒）
#    微信会重新 prepare 消息库，hook 拿到新句柄

# ② 手动解除硬闸（不重启桥）
Invoke-RestMethod 'http://127.0.0.1:17300/api/pollResume' -Method Post

# ③ 最后手段：重启桥
```

**注意 ② 的前提**：你得先让微信真的能打开那个库（即做了 ①）。否则 resume 之后还是会再硬停一次。

---

### 2.3 安静时段

**症状**：白天正常，深夜突然不理人。

**判断**：

```powershell
# 看配置
Get-Content D:\dsh\data\wechat-bot\config.json | ConvertFrom-Json | Select quietHours, quietAllow
```

**默认** `23:00-08:00`，且 `quietAllow: ["at","name"]` 表示安静时段**被 @ 或被点名仍会回**。想彻底静音就设 `quietAllow: []`。

---

### 2.4 概率 / 冷却

**症状**：它偶尔回、偶尔不回，看起来「抽风」。

**这是设计**，不是 bug。见配置项：

| 配置 | 默认 | 含义 |
|---|---|---|
| `replyProbability` | 0.8 | 闲聊插话概率 |
| `minReplyGapMs` | 6000 | 同群两次回复最小间隔 |
| `maxRepliesPer10Min` | 15 | 同群 10 分钟上限 |
| `temperature` | 0.95 | 模型随机性 |

想让它更活跃：调高 `replyProbability`、降低 `minReplyGapMs`。

---

### 2.5 插件没加载

**症状**：面板能开，但「收到/回复」「各群状态」全是 0；DSH 里 `wechat_bot_*` 工具全没了。

**判断**：

```
DSH 面板 → 设置 → 插件，看 `@dsh-external/dsh-wechat-bot` 是不是 active
```

或者直接看日志：

```powershell
Get-Content "$env:USERPROFILE\.dsh\data\super-injector\wechat-bot-plugin.log" -Tail 20
```

**常见原因**：

| 原因 | 日志特征 | 解法 |
|---|---|---|
| 工具重复注册（热重载） | `tool "wechat_bot_status" is already registered` | 已修（`safeRegister`），若还犯 → uninject + inject |
| 语法错误 | `apply 抛异常：SyntaxError` | 检查刚改的文件 |
| 桥连接不上 | `connect() 被调用` 之后没 `bridge 已连接` | 看桥在不在（`Get-NetTCPConnection -LocalPort 17300`）|

## 三、收不到消息（最隐蔽）

### 3.1 消息库是懒加载的

**症状**：机器人刚启动时正常，过一会儿就哑了；或者刚装好就一直是哑的。

**根因**：微信 4.x 的 `message_N.db` **在收发过消息之后才会被打开**。如果启动后一直没人说话，库文件存在但句柄没挂载。

**怎么判断**：

```powershell
# 消息库文件在不在、最近有没有被写
$db = 'D:\Users\Administrator\xwechat_files\<你的wxid>_xxxx\db_storage\message\message_1.db'
Get-Item $db | Select LastWriteTime, Length
# 如果 LastWriteTime 是很久以前 → 微信没在写它 → 懒加载还没触发
```

**怎么解**：在微信里**点开一个聊天**，或者**自己发一条消息**。库一旦被打开，hook 就能拿到句柄。

---

### 3.2 消息库分片会换

**症状**：以前好好的，某天开始收不到消息；但日志显示「数据库轮询就绪」。

**根因**：微信的消息库是**分片**的（`message_0.db` / `message_1.db` / …），用哪个由微信自己决定。桥里写死了逻辑名 `message_0.db`，靠 `resolveShard()` 透明解析成真实分片。如果微信换了分片而缓存没更新，就会「拿着过期列表空转」——**日志显示就绪，但一条消息都收不到**。

**怎么判断**：

```powershell
Get-ChildItem 'D:\Users\Administrator\xwechat_files\<wxid>_xxxx\db_storage\message\' -Filter 'message_*.db' |
  Select Name, Length, LastWriteTime
# 看哪个在最近被写
```

**怎么解**：桥每 5 分钟会自动重扫会话表。想立刻恢复：重启桥，或者调 `POST /api/pollResume`（会强制 `_lastReinitAt = 0`）。

### 3.3b contact.db 读不到（昵称退化成 wxid）

**症状**：

```
桥日志每 5 分钟刷一行：
  联系人库暂不可用（SQL 失败(contact.db) status=-1:
  get database handle which named contact.db failed）→ 改用 session.db 兜底

面板「群与人」页里，成员昵称显示 wxid_xxx
```

**这个坑踩了两次，是两个独立的根因叠在一起。**

#### 根因①：hook 只挂了 open_v2，而微信走的是 open(v1)

```
/Debug/ApiTable 的 slots 地址（module_base = Weixin.dll）：
  open        在 Weixin.dll 内      ← 微信核心开库走这个
  open_v2     在**另一个模块**      ← WCDB 封装层，微信从不去调
  db_filename 在 Weixin.dll 内
```

只挂 `open_v2` 时 `open_v2_names` 恒为 0，`contact.db` 这类「只在启动时 open 一次」的库
永远进不了 `db_registry`。

**已修**（2026-10-22）：在 `installCode()` 里补挂 `api->open`（v1 入口），
`/Debug/ApiTable` 会显示 `open_v1_code: true`。

#### 根因②：trusted 判据拿 tick（open 时间）判死

```cpp
// 修之前
trusted = (e.fail < 2) && (nowMs() - e.tick < 300000);
//                                    ↑ tick 是「open/prepare 入口时间」
//                                      不是「上次成功读的时间」
```

`contact.db` 只在微信启动或插件每 5 分钟读一次时被碰一下，`tick` 必然老化到 5 分钟，
被判成死句柄 → `retireHandle()` 立墓碑 → **该库永久读不到**，直到微信重新 open。

**已修**（2026-10-22）：分级判据 ——

```cpp
trusted = (e.fail < 2);                          // fail 是硬条件
if (trusted && (nowMs() - e.tick >= 300000)) {   // tick 老了不直接判死
    trusted = verifyName(h, dbname);             // 先 SEH 验名字
}
```

`verifyName → safeDbName → sehDbFilename` 全程有 SEH，对野指针只返回 false、**绝不崩**。

**外加双保险**：桥的重扫间隔和插件的名字缓存都从 5 分钟压到 **2 分钟**，
让 `tick` 永远新鲜，连 `verifyName` 那次开销都省掉。

#### 怎么验证修好了

```powershell
# ① hook 挂上了吗
Invoke-RestMethod 'http://127.0.0.1:30001/Debug/ApiTable' -TimeoutSec 10 |
  ConvertTo-Json -Depth 4 | Select-String 'open_v1_code|open_v2_code|prepare'

# ② 四个库都能读吗（全 status=0 就是好的）
foreach ($db in 'contact.db','contact_fts.db','session.db','message_1.db') {
  $b = @{ optDbName=$db; SQL='SELECT count(*) AS n FROM sqlite_master' } | ConvertTo-Json -Compress
  $r = Invoke-RestMethod 'http://127.0.0.1:30001/QueryDB/execute' -Method Post -Body $b -ContentType 'application/json'
  "$db  status=$($r.status)"
}

# ③ 真实昵称
$b = @{ optDbName='contact.db'; SQL='SELECT username, nick_name FROM contact LIMIT 5' } | ConvertTo-Json -Compress
(Invoke-RestMethod 'http://127.0.0.1:30001/QueryDB/execute' -Method Post -Body $b -ContentType 'application/json').data
```

#### 如果还犯

先看 `/Debug/ApiTable` 里 `open_v1_code` 是不是 `true`：

```
false → 装的 DLL 是旧版（没有 open(v1) hook），换最新 DLL
true  → 看 /Debug/DBRescan 里 contact* 在不在注册表
         不在 → 微信没重新 open（点开通讯录或重启微信）
         在但 fail>0 → 句柄真的坏了，微信重开
```

## 四、微信崩溃

### 4.1 DB 句柄野指针（本项目最严重的崩溃）

**症状**：微信托盘图标突然消失，`%APPDATA%\Tencent\xwechat\crashinfo\reports\` 多一个 6MB 左右的 `Weixin_xxx.dmp`。

**历史案例**：

```
2026-10-22 13:34 / 16:43 / 17:13 / 20:13   ← 同一个模式
```

**根因**（以 20:13 那次为例）：

```
17:17   微信启动，DLL 装好，一切正常，稳了 2.9 小时
20:05   桥重启（为了改日志策略）
20:05   桥开始探测 message_1.db
20:09   DLL 判句柄「不可信」（tick 超 5 分钟）→ retireHandle 立墓碑
20:10   看门狗重试 → 重扫 → 又拿到不正的句柄
20:13   野指针 sqilte3_prepare → 微信崩
```

**怎么判断是这个问题**：崩溃 dump 的时间点，正好在桥日志出现 `轮询暂停` / `get database handle which named message_N.db failed` 之后几分钟内。

**已做的防护**（桥侧，不动 DLL）：

```
① tick 探测失败 3 轮     → 硬停，不再探测
② init 启动失败 6 次     → 硬停，不再探测
③ 硬停后 paused() 恒 true → 一次查询都不发
④ 硬停只认三种恢复：微信重登 / POST /api/pollResume / 重启桥
```

**想根治**：改 DLL 里 `db_mgr.cpp` 的 trusted 判断 —— 不要用 `tick`（open 时间）判死，改成 `fail` 计数 + SEH 保护下的 `verifyName()` 实际验证。这需要重编译 + 退微信部署，风险较高。

---

### 4.2 中文路径

**症状**：微信装在中文目录（如 `D:\微信\Weixin.exe`）时，`lookup_ok` 一直是 0 或很小，读不到任何库名。

**根因**：DLL 里有一处把非 ASCII 字符（`c > 0x7E`）当成非法并拒绝，导致中文数据目录永远拿不到库名。

**已修**（2026-10-22 之前）。如果还犯，检查 DLL 是不是最新版。

---

### 4.3 崩溃 dump 怎么读

```powershell
# 列出所有 dump，按时间倒序
Get-ChildItem "$env:APPDATA\Tencent\xwechat\crashinfo\reports" -File |
  Sort LastWriteTime -Descending | Select -First 5 |
  Format-Table LastWriteTime, @{n='MB';e={[math]::Round($_.Length/1MB,1)}}, Name
```

**关键判断**：dump 的时间点和桥日志的异常时间点对不对得上。

```powershell
# 桥日志找异常
Get-Content 'D:\微信deepseek\data\logs\bridge-YYYY-MM-DD.log' |
  Select-String '轮询暂停|轮询失败|get database handle'
```

## 五、面板打不开

### 5.1 端口不对

**面板地址永远是**：

```
http://127.0.0.1:<你启动 DSH 时给的端口>/wechat-bot
```

**端口不用猜**：`dsh web` 启动后会**自动打开浏览器**，那个页面的地址栏就是你的 DSH 地址。在末尾加 `/wechat-bot` 回车即可。

**打开面板后**，左上角会显示它自己的完整地址，**点一下就能复制**。

---

### 5.2 没登录 DSH

**症状**：`HTTP 401`。

**这是正常的** —— 面板复用 DSH 的登录态，你要先登录 DSH 主页。

**注意**：面板**只监听回环地址**，别人默认打不开。要让局域网访问：

```powershell
dsh web --port 3080 --host <你的内网IP> --trusted-host <你的内网IP>:3080
```

---

### 5.3 插件没挂载

**症状**：面板 `HTTP 404`（不是 401）。

**判断**：

```powershell
Get-Content "$env:USERPROFILE\.dsh\data\super-injector\wechat-bot-plugin.log" |
  Select-String '面板已挂载'
# 应该有：面板已挂载：/wechat-bot
```

**没挂载的原因**：webServer 服务没就绪（插件会重试 5 分钟，2 秒一次）。看日志有没有：

```
面板：没有可用的 webServer 服务，已跳过挂载
```

如果是这个 → 重启 DSH。

## 六、Hook / DLL

### 6.1 DLL 加载失败

**症状**：微信起不来，或者弹「无法定位程序输入点」。

**必查三项**：

```powershell
# ① 文件在不在
Test-Path 'D:\wxhook\wx4110\version.dll'

# ② 大小对不对（正常约 770KB）
[math]::Round((Get-Item 'D:\wxhook\wx4110\version.dll').Length/1KB, 1)

# ③ 有没有备份（换过的痕迹）
Get-ChildItem 'D:\wxhook\wx4110\version.dll.bak-*' -EA SilentlyContinue
```

**回滚**：

```powershell
# 把最新的备份换回去
$bak = Get-ChildItem 'D:\wxhook\wx4110\version.dll.bak-*' | Sort LastWriteTime -Desc | Select -First 1
Copy-Item $bak.FullName 'D:\wxhook\wx4110\version.dll' -Force
```

**注意**：换 DLL 前**必须完全退出微信**（托盘右键 → 退出），否则文件被占用，复制会失败甚至写坏。

---

### 6.2 微信版本不对

**只支持 微信 4.1.10.27 x64**。

```powershell
# 看版本目录
Get-ChildItem 'D:\wxhook\wx4110' -Directory | Where-Object { $_.Name -match '^\d+\.\d+\.\d+\.\d+$' } | Select Name
# 必须是 4.1.10.27
```

**其他版本一定不行**（hook 的偏移是硬编码的）。

---

### 6.3 QueryDB 坏了

**症状**：`lookup_ok` 一直是 0，或者日志里有：

```
get database handle which named message_0.db failed
联系人库不可用（该构建的 /QueryDB 坏了）
```

**自查**：

```powershell
Invoke-RestMethod 'http://127.0.0.1:30001/Debug/DBRescan' | ConvertTo-Json -Depth 4
# 看 counters.lookup_ok / registry.named / db_count
```

| 字段 | 正常值 | 含义 |
|---|---|---|
| `lookup_ok` | 上千 | 成功查过的库名次数 |
| `registry.named` | >= 8 | 有名字的句柄数 |
| `db_count` | >= 8 | 扫到的库文件数 |

**如果 `lookup_ok` = 0 且 `named` 很少** → 要么是中文路径问题（见 4.2），要么 DLL 不是这个项目编译的。

> ⚠️ **官方 release 的 version.dll 用不了** —— 它的 QueryDB 是坏的（`g_IsLogin` 永远 0），也没有回调推送实现。必须用本仓库补丁编译出来的。

## 七、功能不工作

### 7.1 识图

**症状**：群里有人发图，机器人只看到 `[图片]`。

**必查**：

```powershell
# ① 视觉模型配了吗
Get-Content D:\dsh\data\wechat-bot\config.json | ConvertFrom-Json | Select visionProvider, visionModel, visionOnImage

# ② pythonExe 对吗（识图要调 Python）
Get-Content D:\dsh\data\wechat-bot\config.json | ConvertFrom-Json | Select pythonExe
```

**常见坑**：

- `visionOnImage: false` → 根本没开
- `pythonExe` 填的相对路径 `python`，但服务进程 PATH 里没有 → 改成绝对路径
- 图片是 **V2 加密的 .dat**，需要微信客户端真的解密过一次才会出现明文

---

### 7.2 语音

**症状**：发语音它没反应，或者转写失败。

**依赖 3 样东西**：

| 依赖 | 判断 | 说明 |
|---|---|---|
| 本地 SenseVoice | DSH 的 `speech-to-text-sensevoice` 插件是否 active | 不需要 API key |
| 语音文件能定位 | `<数据目录>\msg\attach` 下有没有 `.silk` | 没人播放过的老语音磁盘上没有 |
| ffmpeg | `where.exe ffmpeg` | 转码用 |

**让它发语音**要开两处开关：

```
hook 侧:  <客户端目录>\hook-voice-send.on
插件侧:   config.voiceSay = true
```

### 7.3 视频

**症状**：发视频它只看到封面，或者完全看不懂。

**关键**：**微信自己的视频消息（type 43）** 和 **链接视频（抖音/B站等）** 是两条完全不同的管线。

| 类型 | 需要什么 |
|---|---|
| 微信视频消息 | 在客户端里**点开播放过一次**（否则只有明文封面 JPG） |
| 链接视频（抖音/B站/小红书） | `yt-dlp` + `ffmpeg`，且要能下载 |

**抽帧策略**：按时间**每秒一帧**，最多 20 帧，拼成联系表（contact sheet）给视觉模型。

### 7.4 表情包

**症状**：它不发图，只发文字。

**判断**：

```powershell
# 表情包库有多少张
Invoke-RestMethod 'http://127.0.0.1:30001/Debug/DBRescan' | Out-Null
# 或看面板「表情包」页
```

**常见原因**：

| 原因 | 解法 |
|---|---|
| 库里没图 | 让群友发几个表情包，它会自动收藏 |
| `stickerChance` 太低 | 调高（默认 0.22） |
| 图都太大了（微信限制 5MB） | 删掉大图 |

### 7.5 生图（表情包）

**症状**：点「生成」一直失败。

**配置文件**：`D:\微信deepseek\data\image-gen.json`

**必查**：

```powershell
Get-Content D:\微信deepseek\data\image-gen.json | ConvertFrom-Json | Select backend, apiUrl, model, mode, style
```

**常见坑**：

| 现象 | 原因 | 解法 |
|---|---|---|
| `503` / 一直排队 | Agnes 的 i2i 队列很小，高峰期会一直 503 | 换 `style: openai` + 别的家（xAI / GLM）|
| key 无效 | `keyRef` 指向的凭据没有 | 填 `apiKey` 明文（桥认这个）|
| 改完不生效 | 桥读配置有缓存 | **重启 wx-bridge** |
| 角色不像 | 用了 t2i（文生图）| 改 `mode: i2i`，靠参考图锁角色 |

### 8.1 日志膨胀（已修）

## 十、救命三招

按顺序试，通常前两个就够：

```
① 点开一个微信聊天窗口
   → 逼微信打开消息库 → hook 拿到句柄 → 轮询自动恢复

② POST /api/pollResume
   → 解除轮询硬闸 → 强制重扫会话表

③ 重启 wx-bridge
   → 清掉所有缓存状态，从零开始
```

**如果三招都不行**，收集这些信息再报问题：

```
· 桥日志最后 50 行
· 插件日志最后 50 行
· Invoke-RestMethod /Debug/DBRescan 的完整输出
· 崩溃 dump 列表（如果有）
· 微信版本（必须是 4.1.10.27）
```
