## 三、怎么用

1. 加能力前先搜本文件关键字（`mmsns` / `cdntask` / `aeskey` / `TimelineObject`）
2. 命中后看「引用点 RVA」，用 `python tools_rva_dump.py <dll> <rva> 48` 取码
3. 确认是目标函数后，按 `include/global.h` 的格式加偏移 + 特征码
4. 小号验证 → 回归测试

## 六、朋友圈发布链路（完整逆向记录，4.1.10.27）

### 已确认的函数与结构

| 项 | 值 | 说明 |
|---|---|---|
| mmsnspost 请求构造+发送 | `0x04EB0B90` | 唯一调用点 `0x04EAF2EA`；内含 CoCgiSendRequest 与 `/cgi-bin/micromsg-bin/mmsnspost` |
| 同 CGI 另一条路径 | `0x04EB3910` | 小函数，会 malloc 出路径字符串、从 P1 拷字符串到 P3 |
| 业务层 | `0x04EAE7F0` | `(rcx=对象, rdx=&结构)`，内部自己构造 P1/P3/P4/P5 |
| UI 层 | `0x04EABFBA` | 引用 publish_* 样式键，无静态调用者（Qt 信号槽） |
| SNS 管理器单例 | 全局 `RVA 0x0A83AB20` | 取法：`0x180410C0 = { mov rax,[rip+0xA7F9A59]; ret }` |
| P2 来源 | `[[singleton]+0x10]` | 虚方法返回值 |
| P3 构造函数 | `0x04DA2BB0` | P3 是 0x1A0 字节对象，vtable 写在 +0x00 |
| P3 复制构造 | `0x04DB9D20` | `(dest, P3)` |
| 提交函数 | `0x04E90530` | 吃 16 字节/元素的操作数组，按首字段类型 2/4/6/10 分发 |

### 参数模型

```c
P1 (rcx) = 输出对象，至少 0x38 字节；+0x18 处是 std::string(buf@18/size@28/cap@30)
P2 (rdx) = SNS 单例的虚方法 [[singleton]+0x10] 返回值
P3 (r8)  = 0x1A0 字节对象，必须先调 0x04DA2BB0 构造
P4 (r9)  = std::string(buf@00/size@10/cap@18)
P5 (栈)  = { DWORD type(=0); DWORD flag(=0x1D4C0); std::string text(@+08); void* extra(@+28) }
           调用方常量：movabs rax, 0x1D4C000000000（低 32 位 type=0，高 32 位 flag）
```

### 为什么外部调用会崩（根因）

在 hook 里按上述模型调用 `0x04EB0B90`，稳定在 `RVA 0x3C95E0` 空指针解引用（`mov rax,[rdi]`，rdi=0），
**且 8 种参数变体（含故意不构造 P3 的对照组）崩溃地址完全一致** → 与传入参数无关。

反向调用链追到的路径：

```
0x3C95E0 (崩)  ← 0x3C9299  ← 0x3C9080   ← 0x3C9019  ← 0x3C8FE0  ← 0xCC113B  ← 0xCC10A0
                                                                                     ↑ 无直接调用者（虚函数）
```

`0xCC10A0` 特征：`xchg byte [rcx+0x178],1`（init-once）、`lock cmpxchg [rcx+8]`（引用计数）、
`[rcx+0xb0]/[rcx+0xc0]/[rcx+0xf0]`（任务队列字段）。`0x3C8FE0/0x3C9080` 是 std::function 调用器。

**结论：`0x04EB0B90` 会把请求投递到微信内部任务调度器（异步）。在外部线程直接调用时，
调度器上下文未初始化 → 空指针。要打通必须还原任务派发对象（init-once + 引用计数 + 队列）的构造与登记。**

### 动态调试为什么不可行

微信 4.x 有反调试：软件断点（写 0xCC）和**纯硬件断点（只改 DR 寄存器、不碰代码）**都会让客户端退出，
两次实测均崩。因此拿不到运行时参数与真实调用栈。
